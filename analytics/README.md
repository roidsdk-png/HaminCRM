# اجرای محلی تحلیل و هوش مصنوعی

این بخش از صفحهٔ /analysis در CRM، درگاه احراز هویت، سرویس Python و پردازش پس‌زمینه تشکیل شده است. محیط توسعه و انتشار فعلی سرور از SQLite تحلیلی استفاده می‌کنند. مسیر اجرای بومی با systemd در [مستند استقرار](../docs/native-deployment.md) توضیح داده شده است. پیکربندی PostgreSQL و pgvector نیز برای بررسی جداگانه موجود است.

## راه اندازی ویندوز

دستورها را در پوشهٔ crm اجرا کنید.

```powershell
python -m venv --system-site-packages .venv-analytics
.\.venv-analytics\Scripts\python.exe -m pip install -r analytics/requirements.txt
npm run dev:analysis
```

صفحهٔ پیش‌نمایش در http://localhost:3143/analysis و سرویس خصوصی در 127.0.0.1:8091 اجرا می‌شوند. اجراگر، مهاجرت‌های محلی را اعمال می‌کند، توکن ارتباط داخلی می‌سازد و سرویس، CRM و همگام‌سازی تدریجی را راه می‌اندازد. توقف اجراگر، فرایندهای متعلق به همین اجرا را می‌بندد.

تنظیمات خصوصی محلی در analytics.env.local ذخیره می‌شوند. فایل و پایگاه تحلیلی از Git کنار گذاشته شده‌اند. اجراگر دو مقدار ANALYTICS_SERVICE_URL و ANALYTICS_INTERNAL_TOKEN را در .dev.vars محلی هماهنگ می‌کند.

## اتصال مدل

در «تحلیل و هوش مصنوعی ← منابع و تنظیمات»، مالک می‌تواند ارائه‌دهندهٔ OpenAI، Google AI Studio / Gemini، OpenRouter، AvalAI، GapGPT یا سرویس سازگار با OpenAI را انتخاب کند. شناسهٔ دقیق مدل و کلید API همان سرویس را وارد و ذخیره کنید. مدل باید ابزارهای تابعی و خروجی JSON را پشتیبانی کند. ذخیرهٔ فرم هیچ فراخوانی مدل انجام نمی‌دهد و پس از ذخیره، تنظیمات بدون راه‌اندازی مجدد اعمال می‌شوند. هنگام وجود تحلیل صف‌شده یا در حال اجرا، تغییر تنظیمات تا توقف یا پایان آن تحلیل‌ها متوقف می‌شود.

ارائه‌دهنده، مدل و کلید بردارسازی را نیز می‌توان مستقل تنظیم کرد. در حالت استفاده از ارائه‌دهندهٔ تحلیل، کلید تحلیل فقط زمانی به بردارسازی می‌رسد که ارائه‌دهنده و نشانی مقصد یکسان باشند. مدل بردارسازی خالی یعنی جست‌وجوی معنایی غیرفعال است. کلید خالی در فرم، کلید ذخیره‌شده را حفظ می‌کند؛ حذف نیازمند انتخاب صریح است. تغییر مقصد با کلید موجود به ورود کلید مقصد جدید یا حذف صریح کلید قبلی نیاز دارد.

| گزینه | نشانی پیش‌فرض |
| --- | --- |
| OpenAI / API مدل‌های GPT | https://api.openai.com/v1 |
| Google AI Studio / Gemini | https://generativelanguage.googleapis.com/v1beta/openai |
| OpenRouter | https://openrouter.ai/api/v1 |
| AvalAI / اول ای‌آی | https://api.avalai.ir/v1 |
| GapGPT / گپ جی‌پی‌تی | https://api.gapgpt.app/v1 |
| سفارشی | نشانی HTTPS سرویس سازگار؛ HTTP فقط برای loopback محلی |

کلیدها فقط در فایل خصوصی analytics-data/provider-settings.json ذخیره می‌شوند و از API خواندن تنظیمات بازگردانده نمی‌شوند. فایل از Git و بستهٔ انتشار سورس کنار گذاشته شده و در سرور، بیرون پوشهٔ نسخهٔ برنامه نگهداری می‌شود. در Linux مجوز فایل ۶۰۰ است؛ در Windows دسترسی از مجوزهای پوشهٔ پروژه پیروی می‌کند. این فایل حاوی کلید محرمانه است و باید با نسخه‌های پشتیبان خصوصی مدیریت شود. تنظیمات ثبت‌شده در پنل بر متغیرهای محیطی تقدم دارند.

روش جایگزین، تنظیم ANALYTICS_PROVIDER به openai، google، openrouter، avalai، gapgpt یا custom و مقادیر ANALYTICS_API_KEY و ANALYTICS_MODEL در analytics.env.local و راه‌اندازی مجدد است. برای ارائه‌دهندهٔ آماده، ANALYTICS_API_BASE_URL را خالی بگذارید. برای نشانی واسط از custom استفاده کنید. متغیرهای ANALYTICS_EMBEDDING_PROVIDER، ANALYTICS_EMBEDDING_API_KEY، ANALYTICS_EMBEDDING_API_BASE_URL و ANALYTICS_EMBEDDING_MODEL نیز در فایل نمونه آمده‌اند. فایل تنظیمات پنل را برای بازگشت به روش محیطی، به‌صورت محلی و با مراقبت از کلیدها کنار بگذارید.

OpenAI و ChatGPT دو ارائه‌دهندهٔ جدا در فرم نیستند؛ API مدل‌های GPT با کلید OpenAI استفاده می‌شود. اشتراک ChatGPT جای کلید و اعتبار API را نمی‌گیرد. [توضیح رسمی OpenAI](https://help.openai.com/en/articles/9039756-managing-billing-for-chatgpt-and-the-api-platform)، [قرارداد سازگار Google](https://aistudio.google.com/docs/openai) و [مستندات OpenRouter](https://openrouter.ai/docs/api/reference/embeddings) مبنای این اتصال‌اند.

نشانی و قرارداد سازگار AvalAI از [مستندات رسمی AvalAI](https://docs.avalai.org/en/api-reference/introduction) و GapGPT از [راهنمای رسمی API گپ جی‌پی‌تی](https://aigap.app/platform-v2/docs/models/claude-api) و [راهنمای بردارسازی و RAG](https://aigap.app/platform-v2/docs/use-cases/openwebui) گرفته شده‌اند. هر دو برای چت، خروجی JSON، ابزارهای تابعی و بردارسازی از مسیر سازگار با OpenAI استفاده می‌کنند؛ مدل انتخابی باید قابلیت مربوط را پشتیبانی کند. نام مدل را مطابق پنل همان سرویس وارد کنید. آزمون‌های خودکار با پاسخ ساختگی قرارداد HTTP را بررسی می‌کنند؛ تأیید کلید، دسترسی حساب و کیفیت مدل به آزمون واقعی پس از ورود API نیاز دارد.

هزینه و سقف تعداد رکورد و فراخوانی با متغیرهای فایل نمونه قابل تنظیم‌اند. آمار و ابر واژه به تنظیم مدل نیاز ندارند. وضعیت پیکربندی در رابط نشان داده می‌شود.

سرویس متن و فراداده را پیش از ذخیره و ارسال به API پوشانده‌سازی می‌کند. نام‌های ثبت‌شدهٔ CRM محلی پوشانده می‌شوند. کیفیت پوشاندن نام‌ها و جزئیات هویتیِ آزاد باید در پایلوت واقعی ارزیابی شود.

## داده و راهنماهای آزمون

همگام‌سازی از اطلاعات موجود در دیتابیس محلی انجام می‌شود. فهرست منابع و دادهٔ محیط توسعه با موجودی تولید سنجیده می‌شود. دریافت دادهٔ عملیاتی و ارزیابی انسانی، مرحله‌ای مستقل از تست‌های ساختگی‌اند.

در زبانهٔ «منابع و تنظیمات»، مالک می‌تواند راهنمای معتبر آزمون را با تأیید مرجع وارد کند، واژه‌های عمومی ابر کلمات را تنظیم کند و مصرف پردازش را ببیند. راهنماها در مسیر ANALYTICS_GUIDES_DIR با پیش‌فرض analytics-data/guides ذخیره می‌شوند. هر راهنما دارای testKey، version، source و اطلاعات واقعی نمره‌گذاری یا تفسیر است. نسخهٔ رکورد باید در metadata.testVersion یا metadata.questionnaireVersion معتبر باشد. راهنمای دارای نسخهٔ ناسازگار یا تعریف متعارض انتخاب نمی‌شود. برای اصلاح تعریف، نسخهٔ تازه ثبت کنید. حذف از رابط فقط فایل‌های واردشده از همین رابط را حذف می‌کند.

شناسهٔ مخاطب در محدودهٔ همان منبع مستعار می‌شود. مالک می‌تواند مخاطبان یک فرد را با ثبت مبنای تأیید به هم پیوند دهد یا پیوند را لغو کند. تغییر پیوند در دریافت تدریجی اعمال می‌شود و نتایج وابسته به دادهٔ تغییرکرده از اعتبار می‌افتند. گزینهٔ فیلتر «سوابق هویت‌های تأییدشده» دامنهٔ مخاطب را به همان پیوندها گسترش می‌دهد. ابزار تحقیق می‌تواند گروه آزمون را با گفتگوهای قبل یا بعد از آزمون مرتبط کند و پوشش پیوند را گزارش دهد. شباهت نام مبنای پیوند خودکار نیست.

برای گزارش نتیجهٔ هر فرد، ابزار تحقیق از latest_per_contact استفاده می‌کند و آخرین تلاش تکمیل‌شده را پیش از شرط نمره انتخاب می‌کند. گزارش تعداد تلاش‌ها از all استفاده می‌کند. رکورد فاقد شناسهٔ مخاطب به‌صورت مستقل می‌ماند. سابقهٔ تحلیل‌های همان حساب در زبانهٔ مربوط قابل بازیابی است.

## آزمون ها

```powershell
.\.venv-analytics\Scripts\python.exe -m unittest discover -s analytics/tests -v
python scripts/analysis-bridge-test.py -v
npx tsc --noEmit
npm run lint
npm run build
npm run test:release
```

برای بررسی مسیر واقعی رابط و داده، اجراگر محلی را روشن نگه دارید و دستور زیر را اجرا کنید.

```powershell
python scripts/analysis-live-test.py
```

این آزمون در دیتابیس محلی دو منبع و رکوردهای ساختگی با شناسهٔ تصادفی ایجاد می‌کند. شمارش نقش‌ها، فیلتر نمره، لینک شواهد، کنترل مبدأ، ثبت و لغو پیوند هویت، واژه‌نامه، راهنمای آزمون و همگام‌سازی ویرایش را می‌سنجد و سپس داده‌های همان آزمون را حذف و حذف‌ها را همگام می‌کند.

آزمون‌های مدل از پاسخ‌های ساختگی مخصوص تست استفاده می‌کنند. نتایج آن‌ها درستی شمارش، قرارداد، کنترل دسترسی، شواهد، صفحه‌بندی، راهنما، لغو و بازیابی را بررسی می‌کند. کیفیت معنایی مدل، precision و recall فارسی، وفاداری نگارش و بار دادهٔ واقعی در پایلوت مستقل سنجیده می‌شوند. ابزار و قرارداد این ارزیابی در [EVALUATION.md](EVALUATION.md) آمده است.

برای تکرار مجموعهٔ آزمون روی PostgreSQL محلی، ANALYTICS_TEST_POSTGRES_URL را به دیتابیس آزمایشی روی loopback بدهید و scripts/analysis-postgres-test.py را با Python محیط مجازی اجرا کنید. اجراگر schemaهای تصادفی می‌سازد و فقط همان‌ها را پاک می‌کند. گزینهٔ --pattern نام فایل تست منتخب را می‌گیرد. مجموعه اکنون ۱۸۹ تست دارد؛ ۴۲ تست آن تنظیمات و قرارداد ارائه‌دهنده، از جمله AvalAI و GapGPT، را بررسی می‌کنند. روی SQLite، یک تست ویژهٔ مهاجرت PostgreSQL کنار گذاشته می‌شود. بررسی PostgreSQL 16.11 و بازآزمایی ماژول ارائه‌دهنده پس از اصلاح پارامتر تست موفق بودند. افزونهٔ pgvector در این اجرای ویندوز در دسترس نبود؛ مسیر جایگزین بردار JSON بررسی شد. اجرای تصویرهای Docker و افزونهٔ برداری باید پیش از استقرار احتمالی جداگانه بررسی شود.

## وضعیت انتشار

بخش تحلیل با تأیید مالک روی https://crm.haminyar.ir/analysis به‌صورت بومی و بدون Docker منتشر شده است. کلید و شناسهٔ مدل از «منابع و تنظیمات» ثبت می‌شوند. آزمون قراردادهای اتصال با پاسخ ساختگی انجام می‌شود؛ کیفیت و دسترسی مدل واقعی پس از ثبت کلید باید بررسی شود.
