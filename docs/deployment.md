# انتقال CRM به سرور نهایی

نسخه فعلی با Cloudflare Worker و دیتابیس D1 ساخته شده است. اطلاعات ورود SSH، توکن پیام‌رسان‌ها و کلید هوش مصنوعی در CRM ذخیره نمی‌شوند.

## ترتیب انتقال

1. دامنه نهایی و HTTPS فعال می‌شود.
2. دیتابیس مرکزی ساخته و تمام migrationهای پوشه `drizzle` اجرا می‌شوند.
3. ورود مدیران فعال و اولین مالک سامانه ثبت می‌شود.
4. آدرس `/api/health` باید وضعیت `ok` و اتصال دیتابیس را نشان دهد.
5. برای هر منبع، کلید جداگانه از صفحه «مدیریت منابع» ساخته می‌شود.
6. فقط `CRM_URL` و کلید همان منبع روی سرور ربات یا آزمون قرار می‌گیرد.
7. ابتدا یک رویداد آزمایشی و سپس جریان واقعی هر منبع کنترل می‌شود.

اگر مقصد یک VPS معمولی باشد، قبل از انتقال باید نوع سیستم‌عامل، روش اجرای Node و نوع دیتابیس آن مشخص شود؛ چون نسخه فعلی مستقیماً برای Worker و D1 آماده شده است.
